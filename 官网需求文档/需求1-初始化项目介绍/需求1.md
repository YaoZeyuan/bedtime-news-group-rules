# 需求1: 初始化项目官方网站

## 背景

这是一个用于维护“睡前消息讨论群（非官方）”群规、释规案例与变更历史的仓库。项目需要基于 Vite + Vue3 + TypeScript 搭建一个前端官网，用于对外介绍群组定位、群规、荣誉殿堂和相关公开资料。

项目预计通过 Vercel 部署在 `not-official-bedtime-news-group.yaozeyuan.online` 域名上。

## 已确认需求

1. 官网不展示入群方式，不对外公开加群入口。
2. 群规全文需要公示，内容来源固定为 `./群组文档/rule.md`，文件格式固定为 Markdown。
3. 群规内容会经常变动，但官网不希望因每次群规更新而重新部署。
4. 荣誉殿堂需要放在显眼位置，用于感谢发电群友与说明赞助权益。
5. 官网需要带有群文化风格，可参考 `./群组文档/群聊梳理` 中 7 篇示例进行归纳，但示例本身后续预计不会更新，也不会对外暴露
6. 各类外部入口可以放置为按钮，点击后跳转查看。
7. 部署信息仅作为本文档内部使用，不需要展示在网站页面中。

## 不展示内容

1. 不展示任何入群方式、群二维码、邀请链接或联系人。
2. 不直接公开 `./群组文档/群聊梳理` 原文内容，仅从中归纳群文化与页面语气。
3. 不在网站中展示 Vercel 项目配置、构建命令、部署域名解析说明等内部信息。

## 官网内容模块

### 1. 首屏介绍

目标：让访问者第一眼理解这是一个“非官方、规则驱动、AI 辅助治理”的讨论群规则站。

建议展示内容：

- 站点名称：睡前消息讨论群规则站（非官方）
- 核心说明：这是一个观众自发维护的非官方群组规则与自治文档站。
- 免责声明：与《睡前消息》节目官方无组织关联。
- 核心价值短句：理性讨论、资料共享、AI 校准、规则自治。
- 主要按钮：
  - 查看群规
  - 查看荣誉殿堂
  - 查看释规案例
  - 查看变更记录

### 2. 群组简介

内容来源优先参考 `readme.md` 和 `群组文档/rule.md`。

建议展示：

- 群组是“睡前消息”观众自发组建的非官方讨论群。
- 目标是通过理性讨论、资料共享与逻辑推演，提供增量信息，理解现实运行逻辑。
- 管理目标是让最终聊天内容“值得每日通读”。
- 群聊管理采用结果导向的群内自治模式，由群规、AI 判定、管理员执行共同维持秩序。

### 3. 核心规则速览

目标：用较短内容解释群规的主要机制，降低访问者阅读整篇群规的门槛。

建议展示为规则卡片或分组列表：

- 基本纲领：讨论应提供信息增量，追求事实、逻辑与证据。
- AI 审判：任意群友可发起审判，由 AI 结合上下文和群规判断是否违规。
- 管理员执行：群管依据 AI 判定发出警告并执行，不执行需给出理由。
- 警告系统：默认 24 小时有效，明确告知后最长 7 天；累计 3 次后移出群聊。
- Top3 机制：近 30 天警告次数较高的成员新增警告默认延长。
- 讨论秩序：谁主张谁举证，就事论事，不以立场替代论证。
- 编辑保护：涉及编辑本尊的特别规则需要醒目展示。
- 维护氛围：限制低质量刷屏、连续发言、阴阳怪气、人身攻击、隐私暴露等行为。

### 4. 群规全文

目标：展示最新公开群规全文，并解决“群规常变、官网不常部署”的问题。

推荐技术方案：

1. 官网运行时通过浏览器请求 GitHub Raw 内容，读取固定路径的 Markdown 文件。
2. 当前仓库远端为 `YaoZeyuan/bedtime-news-group-rules`，默认分支为 `main`。
3. 可读取地址：
   `https://raw.githubusercontent.com/YaoZeyuan/bedtime-news-group-rules/main/%E7%BE%A4%E7%BB%84%E6%96%87%E6%A1%A3/rule.md`
4. 前端将 Markdown 渲染为 HTML。建议使用安全的 Markdown 渲染方案，例如关闭原始 HTML，或在渲染后进行净化。
5. 页面需要提供加载中、读取失败、重试按钮与“前往 GitHub 查看原文”的兜底入口。
6. 可在构建时内置一份当前 `rule.md` 的快照作为兜底内容，但页面应优先展示 GitHub Raw 的最新内容。

收益：

- 群规更新后，只要推送到 GitHub，官网下次访问即可读取较新的规则内容。
- 官网不需要为每次群规修改重新部署。

风险与处理：

- GitHub Raw 可能有 CDN 缓存，更新不是绝对实时，但通常可接受。
- 如果仓库未来改为私有，浏览器端将无法直接读取 Raw 内容，需要改为 Vercel Serverless API 代理并配置 GitHub Token。
- 如果 GitHub Raw 访问失败，页面展示内置快照和原文按钮。

### 5. 荣誉殿堂

目标：放在首页显眼位置，表达感谢并说明赞助计划。

建议展示：

- 荣誉殿堂标题与感谢文案。
- 发电赞助入口按钮。
- 电费/Token/机器人维护费用收支明细入口按钮。
- 发电等级与权益表，可从 `readme.md` 中现有表格整理：
  - 歌颂者
  - 祈光人
  - 太阳神官
  - 光之祭司
  - 无暗者

### 6. 释规案例库

目标：帮助读者理解规则如何被解释和执行。

内容来源：

- `群组文档/释规案例库/case-database.md`

建议展示：

- 案例问题列表，例如“避免 troll 的适用规则”“Top3 警告的使用方法”“三法司会审的使用方案”等。
- 每个案例可展示标题、摘要和跳转按钮。
- MVP 阶段可先提供入口按钮，后续再做完整案例渲染。

### 7. 变更记录

目标：展示群规版本演进，体现规则是持续迭代的。

内容来源：

- `群组文档/changelog.md`

建议展示：

- 最新版本号与更新日期。
- 最近若干条变更记录。
- 查看完整变更记录按钮。
- 后续可做时间线样式。

### 8. 群文化说明

目标：让官网不只是规则目录，也能体现该群“理性、较真、戏谑、自我治理”的气质。

根据 `群组文档/群聊梳理` 中 7 篇示例，归纳出的群文化方向：

- 高信息密度：话题覆盖 AI、地缘政治、产业、投资、社会政策、教育、生活经验等。
- 证据优先：重视数据、来源、逻辑链条和可验证论据。
- 较真但可修正规则：群规会在争议中不断释义、补充和版本化。
- AI 深度参与：AI 既是讨论工具，也是群规执行的辅助裁判。
- 戏谑与自嘲：内部梗、绰号、调侃和严肃讨论并存，但规则限制人身攻击与恶意嘲讽。
- 宏大议题与日常生活并置：从国际局势、AI 技术到减肥、租房、饮食，都可能成为讨论对象。
- 自治实验感：不到 200 人的群也会认真维护成文法、判例、执行流程与版本记录。

页面表达建议：

- 视觉上可以有“文档站 + 群聊纪事 + 规则法典”的混合风格。
- 文案可以保留一点群内黑话，例如“AI 审判”“释规”“警告”“荣誉殿堂”，但需要给首次访问者解释清楚。
- 不展示具体群聊原文与个人昵称，避免暴露成员隐私。

- 电费/Token 收支明细

具体 URL 优先从 `readme.md` 和 `群组文档/rule.md` 中读取。

## 页面形态建议

MVP 阶段建议做成单页官网：

1. 首屏介绍
2. 荣誉殿堂
3. 群组简介
4. 核心规则速览
5. 群规全文
6. 释规案例库入口
7. 变更记录入口
8. 外部链接按钮区
9. 免责声明

后续如果内容增多，再拆成多页面或增加路由：

- `/rules`
- `/cases`
- `/changelog`
- `/honor`

## 视觉与交互要求

1. 需要响应式适配桌面与移动端。
2. 不做传统营销 landing page，首页应直接呈现可阅读、可跳转、可查看规则的实际内容。
3. 荣誉殿堂在首屏后优先展示，位置应比变更记录和外部链接更靠前。
4. 按钮应明确表达跳转目标。
5. 群规全文区域需要支持 Markdown 基础排版，包括标题、列表、链接、代码样式、表格。
6. 外部链接需要有明确的打开行为，建议新窗口打开。
7. 页面应明确标注“非官方”属性。

## 内部部署信息

这些信息仅供开发和维护使用，不展示在官网页面中。

- 技术栈：Vite + Vue3 + TypeScript
- 部署平台：Vercel
- 目标域名：`not-official-bedtime-news-group.yaozeyuan.online`
- 构建命令：`pnpm build`
- 输出目录：`dist`
- 群规动态读取来源：GitHub Raw `main/群组文档/rule.md`

## 验收标准

1. 网站首页能清楚说明这是“睡前消息讨论群（非官方）”规则站。
2. 页面不展示任何入群方式。
3. 荣誉殿堂在页面中位置醒目，且有赞助入口与收支明细入口。
4. 群规全文可以从 GitHub Raw 动态读取并渲染。
5. GitHub Raw 读取失败时，有可理解的失败提示、重试按钮和兜底入口。
6. 页面提供释规案例库、变更记录、GitHub 仓库等入口按钮。
7. 页面风格体现群文化：理性讨论、AI 辅助治理、规则自治、适度戏谑。
8. 网站在移动端和桌面端均可正常阅读。
9. 部署信息不在官网页面展示。
